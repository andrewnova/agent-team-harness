01 · One-time setup

Install the shared skill.

You need Herdr, Git, and the native CLIs you plan to use, installed and signed in. The supplied skill installer uses Bash on macOS or Linux.

Keep the clone at a stable location. The installer links the same skill into Claude Code, Codex, and the shared skills directory.

Your native model, effort, trust, and permission settings stay in force. Model availability depends on your accounts.

Install from GitHub
git clone https://github.com/andrewnova/agent-team-harness.git
cd agent-team-harness
./scripts/install-team-skill.sh

Already using this clone? Update it when your working tree is clean. If a different skill is installed, use ./scripts/install-team-skill.sh --refresh to preserve a backup and replace it.

Optional: enable native conversation restore

Herdr's official integrations record native session identity for eligible conversation recovery after a server restart. They add hooks to your native CLI configuration. Start fresh agent sessions after installing them.

Official Herdr integrations
herdr integration install claude
herdr integration install codex
herdr integration status

These hooks do not implement a global pause. Integration details.

02 · Start a task

Open your project in Herdr.

Run Herdr from your project directory. If it attaches to an existing session, select or create the workspace for this project.

Inside that workspace's shell pane, confirm the project directory and start codex or claude. That native session becomes your lead.

This workflow starts inside Herdr. Invoking the skill in a desktop chat outside Herdr does not launch a team.

In your terminal
cd /absolute/path/to/your/project
herdr

After starting your native agent inside Herdr
LeadType in the agent prompt
Codex$team Add a settings page and verify saving preferences
Claude Code/team Add a settings page and verify saving preferences

The lead recommends the builder and its scope, asks you to approve or change that choice, and offers an optional adversarial agent. Then it starts the approved work.

A bare /team or $team prepares the workspace and waits for your task. Start a fresh native session if the skill is not visible.

Who does what

The lead reviews.
You choose the team.

Frontend and backend routing guides the recommendation. Your task and explicit choices decide the actual assignment.

Roles in the shared skill
RoleResponsibilitySelection
LeadPlan, delegate, personally review, integrate, and verify.Invoking Claude or Codex
Frontend builderImplement and repair the approved UI scope.Recommend Fable; ask first
Backend builderImplement and repair the approved backend scope.Recommend Codex; ask first
AdversarialChallenge the candidate and the lead's assessment with evidence. A separate agent from both lead and builder.Optional; ask first
  • Mixed tasks may use one builder or separate frontend and backend assignments. The lead explains its recommendation before dispatch.
  • Both runtimes use useful native children within the approved scope and configured limits. Each parent gives them clear assignments, verifies their work, and closes them when done.
  • A declined adversarial check stays declined. Native children do not require a separate approval for each assignment, but cannot be used to recreate that declined role.
  • Unavailable models are reported, never silently substituted.

From task to result

Clear scopes.
Useful evidence.

Herdr provides the workspace and agent controls. The skill defines how the team works together.

  1. 01

    Agree on the assignment

    The lead inspects the project, recommends a builder, and asks whether to add adversarial work. Existing approval covers routine follow-ups on the same task and lineup.

  2. 02

    Build in parallel where it helps

    Workers get bounded scopes and completion criteria. Simultaneous writers use separate worktrees. Parents collect their native children's results.

  3. 03

    Review the actual result

    The lead inspects the complete candidate and source. If approved, a fresh adversarial agent challenges it. The lead evaluates findings and sends justified repairs back to the builder.

  4. 04

    Verify and hand back

    Run relevant checks, including browser verification for UI when available. Report the result, evidence, and remaining gaps. Leave the main tabs available for inspection.

Stay in control

Steer through your lead.

Change the requirement

Tell the lead what changed. It updates affected workers and review criteria while preserving completed work.

Say “pause team”

The lead stops dispatching, asks parents to hold their children, interrupts active workers, and reports what remains active or unverified.

Resume explicitly

An unexplained interruption holds the assignment. The lead inspects existing work before resuming on your instruction.

Pause is an instruction the agents follow, not an enforced global stop. An idle parent does not prove its children stopped. Detaching from Herdr keeps agent processes running.
